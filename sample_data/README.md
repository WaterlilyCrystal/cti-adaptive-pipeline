# Sample Data — Adaptive CTI Pipeline

This directory contains representative input and output data for the Adaptive LLM-Based Threat Intelligence System.

## Structure

```
sample_data/
├── input/
│   └── sample_collected_items.json     # 8 realistic CTI items from diverse sources
└── output/
    ├── sample_ioc_extraction.json      # IOC extraction results (Phase II)
    ├── sample_attck_mapping.json       # MITRE ATT&CK validated mappings (Phase III)
    └── reports/
    │   └── sample_report_nginx_ransomware.md  # Full multi-tier CTI report
    └── sigma_rules/
        ├── detect_nginx_ransomware_T1190.yml  # Sigma rule for T1190
        └── detect_apt29_phishing_T1566.yml    # Sigma rule for T1566.002
```

## Input Data (`input/sample_collected_items.json`)

Contains **8 sample threat intelligence items** collected from:

| Source | Type | Items |
|--------|------|-------|
| NVD/CVE | feed | 1 |
| CISA KEV | feed | 1 |
| AlienVault OTX | feed | 1 |
| Telegram/@cveNotify | social | 1 |
| Telegram/@vxunderground | social | 1 |
| Mastodon/@vxunderground | social | 1 |
| Reddit/r/netsec | social | 1 |
| BleepingComputer RSS | rss | 1 |

Each item represents a normalized database record as stored by the pipeline after Phase I collection and Phase II processing.

## Output Data

### IOC Extraction (`output/sample_ioc_extraction.json`)
Results from the deterministic IOC extraction module (`analysis/ioc_extractor.py`):
- Public IP addresses (private-range filtered)
- CVE identifiers
- SHA-256 file hashes
- URLs (after defanging/refanging)

### ATT&CK Mapping (`output/sample_attck_mapping.json`)
Results from LLM semantic analysis + `analysis/ttp_mapper.py` validation:
- LLM-suggested technique IDs
- Validated techniques (with official names and tactics from MITRE index)
- Rejected techniques (with rejection reason)

### Multi-Tier Report (`output/reports/sample_report_nginx_ransomware.md`)
Example of a full analyst report generated by `reporting/reporter.py`:
- **Executive Summary** — for management/leadership
- **Technical Report** — for security team
- **Operational Report** — for response team

All reports include the mandatory `ANALYST VERIFICATION REQUIRED` notice.

### Sigma Rules (`output/sigma_rules/*.yml`)
Auto-generated detection rules from `analysis/sigma_engine.py`:
- Mapped to MITRE ATT&CK technique IDs
- YAML-validated before saving
- Include false positive guidance and field hints
